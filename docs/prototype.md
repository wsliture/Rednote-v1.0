| 运行形态 | 原生 HTML/CSS/JS + 模拟数据；本地 HTTP 预览；尚未接入真实后端 |
| 本文作用 | 将布局、交互、数据需求、源码定位和 Thymeleaf 迁移汇总为可检索的统一入口 |

**规则优先级与标记：**

- **正式要求**：PRD 定义的产品行为和验收目标；真实前端与服务端必须满足。
- **原型现状**：HTML、CSS、JavaScript 当前实际展示和模拟的行为，不代表后端已经实现。
- **迁移要求**：将原型接入 Thymeleaf/真实服务时需要完成的工作；不据此假定已有 Java 类型、接口或数据库字段。
- 业务冲突以 PRD 为准，视觉以当前原型为准。发现差异时按[差异清单](#prototype-gaps)处理，不默默改变产品规则，也不把模拟机制搬成生产能力。
- 本文的“页面数据”是语义化视图数据需求；`id`、`title` 等实际原型属性仅用于定位，不是已经确定的 Java DTO 或 HTTP 请求契约。
- 本版没有关注、收藏、私信、通知、找回密码、视频、审核、后台内容管理、账号删除等入口。发布表单的临时输入不是“保存草稿”产品功能。

## 1. 快速检索与源码索引

### 1.1 工程师 / Agent 阅读顺序

1. 在下表按页面编号定位页面章节，读取该页的布局、数据、交互表和验收项。
2. 打开对应 HTML 的 `.content` 看主体结构，打开 `#templates` 看重复项、条件表单和对话框。

### 1.4 启动与素材

在项目根目录执行：

```sh
python3 -m http.server 8765 --directory docs/prototype
```

用户端访问 `http://localhost:8765/`，后台访问 `http://localhost:8765/admin.html`。拆分后的原型需要 HTTP 加载其他 HTML，不支持双击文件的 `file://` 预览。运行原型不需要 Spring Boot、Node 构建或前端框架。

预置图片全部位于 `prototype/images/`，不依赖远程请求；森林图同时用于登录背景。图片均为宽 1000px 的 JPEG，总计约 1.6MB，尺寸和来源以素材清单为准。可直接选作头像或发布上传的正常测试文件；其中不包含 PNG/WebP、损坏图片、伪造类型及 10MB 边界文件，正式文件验收需另行准备。原型默认头像是带背景色的昵称首字，不是另一张远程素材；模板定位为 `tpl-avatar`。

## 2. 视觉与响应式规范

### 2.1 设计语言与颜色

用户端以图片为主，白底、红色强调、轻边框、圆角与充足留白；后台沿用品牌色，采用浅灰底、白色面板和紧凑的信息布局。默认浅色主题，不提供主题切换。

| CSS token / 用途 | 当前值 | 使用说明 |
| --- | --- | --- |
| `--red` / 主强调色 | `#ff2442` | 主按钮、Logo、点赞选中、后台选中导航、选项卡下划线 |
| `--ink` / 正文 | `#252525` | 默认文字，Toast 背景 |
| `--muted` / 次要文字 | `#929292` | `.muted` 文字，不代表禁用 |
| `--line` / 结构线 | `#ededed` | 表单面板、分隔线、导航边界 |
| `--soft` / 轻背景 | `#f7f7f7` | 悬停区域；用户端导航选中另用 `#f5f5f5` |
| 后台底色 / 面板边框 | `#f7f8fa` / `#eceef0` | `.admin-shell`、`.panel` |
| 字段错误 | `#d92944` | `.error` |
| 正常状态标签 | 背景 `#edf8f1`、文字 `#3a9862` | 同时显示“正常”文字 |
| 禁用状态标签 | 背景 `#fff0f1`、文字 `#d95a69` | 同时显示“禁用”文字 |
| 提示条 | 背景 `#fff7f0`、文字 `#aa7950` | 发布公开性、密码修改影响等说明 |
| 焦点 | 按钮/链接 `#ff9eac`；输入 `#ffd0d8` | 按钮/链接 3px outline，输入 2px outline |

`--radius:16px` 是现有变量，但组件各自使用下面记录的半径，不应把所有圆角统一替换成 16px。现有图标主要为字符符号，非某个已安装的图标库；不依赖外部字体。

### 2.2 字体、间距与尺寸

字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。

| 元素 / 选择器 | 桌面数值 | 手机覆盖 / 说明 |
| --- | --- | --- |
| `h1` / `h2` / `h3` | 28 / 21 / 16px | 手机普通 `h1` 23px；具体页面有覆盖 |
| `.muted` / `.eyebrow` | 13 / 11px | eyebrow 手机 10px、字距 2px |
| `.logo` | 27px、850 字重、-1.5px 字距 | 手机顶栏 Logo 20px |
| `.row` | flex、gap 12px | 除局部覆盖外沿用 |
| `.btn` | 14px、600 字重；padding 11px 23px；1px 边框；半径 24px | `.small` 为 12px、padding 7px 15px |
| 原生输入 / 选择 / 文本框 | padding 13px 15px；边框 `#e4e4e4`；半径 11px | 占容器宽度；textarea 行高 1.8，可纵向调整 |
| `.formfield` / label | 字段间下边距 25px；label 14px/600、下边距 10px | 字段错误紧随控件 |
| `.error` | 12px；上边距 6px；最小高度 16px | 不用 Toast 替代字段原因 |
| `.formpanel` | 最大宽 760px；padding 34px；半径 20px | ≤800px padding 24px；≤600px 去边框、padding 0 |
| `.reading` | 最大宽 800px、居中 | 发布、编辑、设置主体容器 |
| `.pagehead` / `.back` | 下边距 28px / 22px | 返回链接 13px |
| `.avatar` / `.md` / `.lg` | 30 / 40 / 92px，圆形 | 卡片头像 22px；`.lg` 在手机为 72px |
| `.tabs` | gap 28px；下边距 28px；按钮 14px | 活动项底部红线 3px；设置选项卡下边距 25px |

间距是既有组件的实际值，不建立额外的全局间距替换方案。正文、评论、简介允许长文本换行，不依靠缩小字体避免溢出。

### 2.3 两端外壳

**用户端桌面**：固定左侧栏 224px，padding 36px 24px 24px，层级 15；主体左边距 224px。顶部栏高 104px，padding 20px 44px；搜索最大宽 520px。内容最大宽 1600px，padding 32px 44px 80px，居中。导航为“发现 / 发布笔记 / 我的”，页脚展示登录入口或本人资料设置入口。

**用户端手机**：≤600px 隐藏侧栏，主体左边距 0；顶栏高 78px、padding 16px，显示小 Logo 和搜索框，隐藏桌面右侧账号区。内容 padding 24px 16px 95px。底部固定导航层级 30，padding `9px 10px max(9px, env(safe-area-inset-bottom))`，包含发现、发布、我的；管理员多一个后台入口。发布按钮为 43×32px 红色加号面。当前原型只有“发现”显式高亮，其他手机导航未提供活动态高亮，迁移时不要把这一现状误读为已完成所有活动态。

**后台桌面**：沿用左侧栏宽度，导航仅“数据看板 / 用户管理”，底部可返回用户端。顶栏高 88px、padding 20px 36px；内容 padding 32px 36px 80px；导航字号 14px、圆角 10px，选中浅红背景。后台不复用用户端底部导航。

**后台手机**：≤600px 顶栏高 76px，左侧菜单按钮打开 `tpl-admin-menu` 管理导航弹窗；顶栏保留管理员名称，隐藏头像。内容 padding 25px 16px 80px。表格在自身 `.tablewrap` 内滚动，不能把整页做成横向滚动。

### 2.4 精确响应式规则

媒体查询是累积覆盖；边界值 `600/800/1200/1600px` 按下表包含关系处理。

| 视口宽度 | 瀑布流 | 侧栏 / 主体左边距 | 关键布局变化 |
| --- | --- | --- | --- |
| `w ≥ 1600` | 5 列，列距 22px | 224px | 其余使用基础桌面规则 |
| `1200 < w < 1600` | 4 列，列距 22px | 224px | 1440px 为主要设计验收视口 |
| `800 < w ≤ 1200` | 3 列，列距 22px | 190px | 内容 padding 28px；详情双栏 1:1、图高 600px；筛选为两列 |
| `600 < w ≤ 800` | 2 列，列距 15px | 160px | 顶栏 90px；内容 24px 18px 80px；详情纵向、图高 460px；认证隐藏左侧图片；指标变两列 |
| `w ≤ 600` | 2 列，列距 12px | 隐藏 / 0 | 手机外壳；详情图高 400px；认证去外框；上传图高 100px；筛选单列；抽屉占全宽 |

原型瀑布流使用 CSS `columns` 和 `break-inside:avoid`，不是横向逐行 Grid，也不是第三方 Masonry。后端输出顺序应保持发布时间倒序、ID 倒序；不能按视觉上逐行读取的顺序重排数据库结果。卡片封面高由 `--h` 控制，演示数据为 225/240/265/290/330px 等，缺省 280px；手机乘以 0.75。该高度是展示数据，非要求后端持久化的业务字段。

## 3. 公共组件与状态

<a id="component-c01"></a>
### C01 导航、搜索与身份入口

源码：各页外壳、`bindShell()`。搜索表单 `#search-form`，字段 `name="q"`；提交及点击放大镜行为相同。`data-my-link` 依身份链接到本人主页或登录；`data-guest` 控制游客登录入口；`data-admin-only` 只显示管理员入口。后台导航不得出现内容管理。公开页面中的“我的”和个人设置不能暴露其他用户的私有字段。

<a id="component-c02"></a>
### C02 笔记卡片与瀑布流

模板：`tpl-card`、`tpl-waterfall`、`tpl-like`。结构依次为封面+标题链接、作者头像昵称链接、独立点赞按钮；点赞不应触发卡片跳转。封面半径 15px、`object-fit:cover`，悬停 0.4s 缩放至 1.035。标题桌面 14px/行高 1.65，margin 11px 3px 9px；卡片下边距 27px。手机标题 13px/1.6、margin 8px 1px，卡片下边距 22px，作者最长显示宽度 80px 并省略。头像/标题等可访问名称应使用真实作者和标题。

<a id="component-c03"></a>
### C03 点赞

模板 `tpl-like`；选择器 `data-like`、`data-heart`、`data-count`。未选中 `♡`，已选中红色 `♥`；`aria-pressed` 和 `aria-label` 随状态更新。游客不显示个人选中状态。数据变化与权限规则见 [I06](#interaction-i06)，列表、详情共享同一有效状态。

<a id="component-c04"></a>
### C04 字段、计数、错误与按钮

所有业务字段使用原生 input/textarea/select，并具有 label 或可访问名称；字符上限在输入旁或辅助文本展示。`data-error="字段名"` 定位字段错误；表单级错误使用对应 `#auth-error` / `#publish-error` / `#settings-error` / `#comment-error`。控件禁用透明度 0.45，并显示不可操作光标。正式异步写入期间禁用重复提交，不以 CSS 变灰替代真实 disabled。当前原型大部分字段在提交时校验，计数超过上限仍可继续输入，再给错误，不自动裁剪。

<a id="component-c05"></a>
### C05 图片上传与图片失败

模板 `tpl-upload`、`tpl-upload-add`、`tpl-preview`、`tpl-image-error`。上传区始终三列，桌面 gap 12px、图片高 145px、添加块最小高 180px；手机 gap 8px、图片高 100px、添加块最小高 140px。缩略图圆角 13px；首张左上角标“封面”。每项提供前移、后移、移除；边界方向按钮 disabled，失败项提供独立重试。达到 9 张隐藏添加入口。

文件输入在模板中使用 `id="images"`，头像使用 `id="avatar-file"`；当前两者没有 `name`，不能误认为原型已有 multipart 请求字段契约。单张最大 `10 × 1024 × 1024` 字节，支持 JPEG/PNG/WebP。具体生命周期见 [I04](#interaction-i04)。

笔记图片加载失败占位高 260px，显示“图片暂时无法加载”和“重试”。重试阻止默认卡片跳转，仍失败则保留占位。不得把失败图片当作可正常发布的文件。

<a id="component-c06"></a>
### C06 评论与两层回复

模板 `tpl-comment`、`tpl-reply`、`tpl-reply-group`、`tpl-more`、`tpl-empty-comments`。评论行头像与内容 gap 10px，上下 margin 21px；内容 13px/1.7。回复区左缩进 36px、左边线 2px `#f1f1f1`、内左距 13px。回复不生成第三层，必须显示被回复昵称。时间、回复、本人删除入口位于工具行。评论容器最大高 340px，可内部纵向滚动；提交区不随评论列表滚走。排序、分页及删除级联见 [I07](#interaction-i07)。

<a id="component-c07"></a>
### C07 分批加载与分页

模板 `tpl-load-more`、`tpl-list-end`、`tpl-pagination`。首页/搜索每批 20 条，保留手动“加载更多笔记”入口；距离页底 300px 内触发原型 250ms 延迟加载。加载后保留当前位置。主页/后台采用上一页、页码、下一页，每页 20 条；首页禁用上一页、末页禁用下一页；分页区域显示总条数和页大小。手机允许分页行换行。正式追加请求、去重及列表快照见 [I08](#interaction-i08)。

<a id="component-c08"></a>
### C08 弹窗、确认、预览与抽屉

公共模板 `tpl-modal`、`tpl-confirm`。遮罩为 `#0005`、层级 100、四周 padding 20px；弹窗最大宽 470px、最大高 90vh、内部可滚动、圆角 20px、padding 30px，手机 padding 24px。确认按钮右对齐；取消不能执行写操作。原型支持按钮及 Escape 关闭，不提供点击遮罩关闭。

打开后聚焦第一个可操作控件；Tab / Shift+Tab 在弹窗内循环，关闭后原触发元素仍存在则恢复焦点。对话框有 `role="dialog"` 和 `aria-modal="true"`；迁移时按内容设置可辨识名称。

发布预览 `tpl-preview`：显示当前标题、首图和正文，未填时使用“未填写标题/正文”，按钮“继续编辑”；不创建笔记、不上传文件、不替代提交校验。

用户抽屉 `tpl-user-detail`：右侧、全高、最大宽 430px、padding 32px、左侧圆角 20px；遮罩无外边距。手机全宽、去圆角。资料两列为 90px 标签 + 内容，gap 23px。关闭与普通弹窗一致。

<a id="component-c09"></a>
### C09 Toast 与提示条

`#toast` 固定底部 35px、水平居中、层级 200、最大宽 90%、padding 13px 23px、圆角 12px、字号 13px。原型显示 3300ms，新的提示替换旧提示；`role="status"`、`aria-live="polite"`。用于成功、网络错误和轻量反馈；字段校验、危险操作和持续错误不能仅靠短暂 Toast 表达。提示条 `.notice` 使用浅橙背景，padding 13px 16px、圆角 10px、字号 12px/1.7。

<a id="component-c10"></a>
### C10 加载、空态与不可用

模板 `tpl-loading`、`tpl-error`、`tpl-empty`。初次加载示例为 8 个骨架块，每块高 300px、半径 15px，1.5s 动画；演示按钮“完成模拟加载”仅供原型。通用失败为“暂时没能加载出来 / 网络开了个小差，请稍后再试。”并提供“重新加载”。未知原型路由显示“页面不存在 / 换个入口，继续发现生活。”并提供返回首页。空态 padding 70px 20px、标题 19px；应区分真实无内容、无搜索结果、无用户结果、已删除及无权限，不能用空态掩盖请求失败。

<a id="component-c11"></a>
### C11 后台指标、趋势、筛选与表格

指标基础四列、gap 20px，白色面板边框 `#eceef0`、圆角 14px、padding 24px；值 32px/650。≤1200px 指标 gap 12px、padding 18px；≤800px 两列；≤600px gap 10px、padding 16px、值 27px，隐藏装饰图标。趋势为响应式 SVG，`viewBox="0 0 900 290"`，红色新增用户、蓝色 `#586dab` 发布笔记，手机最小高 170px；点有数值 title，图有可访问摘要，不提供原型未设计的时间范围切换。

筛选布局基础为 `1fr 1fr 150px auto`，gap 16px；≤1200px 两列，≤600px 单列。表格字号 13px、不折行，表头 padding 15px 14px，单元格 18px 14px；容器 `overflow:auto`。状态标签 11px、圆角 6px、padding 5px 9px，含文字，不能只靠颜色区分。

<a id="component-c12"></a>
### C12 原型演示面板（正式产品移除）

右下角 `data-demo` 按钮打开 `tpl-demo`；桌面距右 20px、底 18px、层级 40，手机距右 10px、底 76px。面板可选游客、普通用户、管理员、禁用账号；可选 `normal`、`loading`、`empty`、`error`、`upload-error`、`unknown`、`expired`。提供用户端入口、后台入口和“重置演示数据”；重置需确认，清除本地修改并回首页。身份切换不是公开产品功能，也不提供管理员注册。

<a id="interactions"></a>
## 4. 共享交互规则

<a id="interaction-i01"></a>
### I01 身份、权限与可见性

| 操作 | 游客 | 正常普通用户 | 管理员 | 禁用账号 |
| --- | --- | --- | --- | --- |
| 浏览公开首页/搜索/主页/详情 | 可 | 可 | 可 | 可作为游客浏览 |
| 发布、上传、点赞、评论、回复 | 引导登录 | 可 | 同普通用户 | 不可 |
| 编辑/删除笔记、删除评论/回复 | 不可 | 仅本人 | 仅本人，无额外内容权限 | 不可 |
| 设置、修改密码、退出 | 不适用 | 仅本人 | 仅本人 | 旧会话应已失效 |
| 后台页面和数据 | 不可 | 不可 | 可 | 不可 |
| 禁用/启用普通用户 | 不可 | 不可 | 可，必须确认 | 不可 |

正式权限由服务端验证；隐藏入口仅控制展示。管理员不能禁用管理员，也不能编辑或删除他人内容。禁用立即撤销所有旧会话，历史公开笔记、点赞和评论保留；启用不恢复旧会话。关联 PERM-01～03、ADMIN-01/03。

<a id="interaction-i02"></a>
### I02 登录引导、返回与输入保留

1. 公开浏览不拦截；首次受限操作记住来源，转到登录页。
2. 登录成功返回来源；无来源则首页。用户重新点击原操作，不自动发布、点赞或补发评论。
3. 原型游客直接提交评论时按笔记 ID 暂存文本于内存，返回后回填；点击“回复”的游客会先登录，当前原型不保存该回复目标。
4. 正式会话过期导致表单失败，应留在当前输入上下文，保留文本、成功上传预览和回复目标；离开前说明影响。原型 `expired` 在编辑表单内保留草稿，不代表真实续登已实现。
5. 真实登录返回目标须是受控站内地址；不能直接信任外部传入 URL。退出后刷新或后退不能恢复写权限。关联 UX-01、USER-02/03、NFR-01。

<a id="interaction-i03"></a>
### I03 字段校验、计数与安全展示

| 内容 | 正式规则 | 原型定位 |
| --- | --- | --- |
| 用户名 | trim 后 4–20 位，仅 ASCII 字母、数字、下划线；判重和登录忽略大小写 | `username` |
| 密码 | 8–32 个 Unicode 字符，至少一英文字母与一数字；不 trim；确认一致 | `password`、`confirm`；改密另有 `old` |
| 昵称 | trim 后必填 1–20 字，不要求唯一 | `name` |
| 简介 | trim 后可空，最多 200 字 | `bio` |
| 标题 / 正文 | trim 后分别 1–50 / 1–5000 字，正文保留内部换行 | `title` / `body` |
| 评论与回复 | trim 后 1–500 字纯文本，保留内部换行 | `text` |
| 搜索词 | trim 后最多 100 字；空词回首页列表；超长提示，不截断 | `q` |

普通英文字母和中文各计一字；按 Unicode 字符计数，不用 UTF-16 字符串 `.length` 直接验长。纯空白视为空。前后端执行同样的规则，不能仅依赖浏览器属性；使用 `th:text` / `textContent` 等转义展示，不执行用户 HTML/脚本，不使用 `th:utext` 展示用户输入。原型登录也套用了注册格式校验，这不是服务端错误语义的替代。关联 USER-01/04/05、NOTE-01、COMMENT-01、HOME-02、UX-04、NFR-01。

<a id="interaction-i04"></a>
### I04 图片上传、排序、移除与引用

正式图片状态：待上传 → 上传中 → 成功/失败；失败可独立重试，也可移除。上传中或失败未处理时禁止成功提交笔记。JPEG/PNG/WebP、单图最大 10MB（含边界），先做客户端提示，再由服务端验证实际类型和可解码性；损坏、伪造类型、超限应拒绝，不清空其他成功图片。

图片有序、同篇不重复，首张为封面；前移/后移后马上更新标识，移除后紧邻图片顺序连续。上传成功得到文件标识和预览地址，不等于笔记已保存。保存只关联本人图片，头像也相同。头像在资料保存成功前不替换原引用。

移除旧图、删笔记或换头像，只能在业务保存成功后解除对应引用。不能在点击“移除”时立刻无条件删除物理文件；取消编辑保留旧图。共享图片有其他引用继续可用；无引用文件由服务端按连续 24 小时规则清理，至少每小时执行，原则上满 25 小时前完成。该清理没有前台“清理全部文件”按钮。

**原型现状**：FileReader 读取为 data URL，以浏览器 `file.type` 和 Image 解码验证；同一图片用 data URL 比较去重；`upload-error` 新选图片置失败，重试直接模拟成功，无真实请求、上传进度、引用保护或定时清理。关联 FILE-01～04、NOTE-01/03/04。

<a id="interaction-i05"></a>
### I05 发布、编辑、预览与未保存离开

- 表单输入与已发布版本分离。新发布必须有完整标题、正文和 1–9 张成功图片；编辑回填同样字段，按同样规则校验。
- 成功前禁重复提交，保存失败保留全部输入和成功上传预览；保存整体成功后才更新列表与详情。编辑保留原发布时间并记录更新时间。
- 预览只显示当前输入，不触发发布；未填字段有占位文案。点击“继续编辑”关闭预览。
- 原型文字修改、添加、排序、移除图片后进入 dirty。点击取消显示“放弃本次修改？”，点击返回/导航显示“离开编辑页面？”；取消确认留在表单，确认丢弃后再离开。刷新由浏览器原生 beforeunload 提示，不能要求浏览器显示自定义文案。
- 当前原型“取消”最终回首页；编辑页上方“返回笔记”最终回原详情。不要把二者混成同一跳转。
- 这些是未保存输入保护，没有自动保存、草稿列表或恢复跨刷新草稿功能。关联 NOTE-01/03、UX-01/04/05/07、NFR-02。

<a id="interaction-i06"></a>
### I06 点赞、取消与状态同步

游客操作按 I02 登录；登录用户可赞自己的有效笔记。每人每篇最多一个有效赞，点赞和取消均幂等，计数不为负；列表与详情保持服务端确认的一致状态。请求失败提示并恢复确认状态，不把失败显示成成功。

原型通过 `rn-likes` 中的 `用户ID:笔记ID` 保存状态、修改本地计数，并更新当前 DOM 同篇的所有点赞按钮；切换页面后重绘。该逻辑不是并发幂等方案，也不证明跨标签页同步。正式可选择等待确认再更新，或在乐观更新后回滚，但对用户的最终状态与失败反馈必须一致。关联 LIKE-01/02、UX-05、NFR-02。

<a id="interaction-i07"></a>
### I07 评论、回复、展开与删除

主评论按创建时间倒序、ID 倒序，每页 20 条；回复按创建时间正序、ID 正序，每页 20 条。回复主评论或具体回复都归同一主评论，不产生第三级。评论总数包括回复。

| 触发操作 | 校验/权限 | 成功结果 | 失败反馈 |
| --- | --- | --- | --- |
| 发送主评论 | 登录、有效笔记、1–500 字 | 添加到最新主评论，更新总数，成功才清空输入 | 字段原因或请求失败；保留输入 |
| 点击回复 | 登录、目标仍有效 | 输入区显示“回复 昵称”，聚焦文本框，保留已有文本 | 目标失效提示刷新，不自动换对象 |
| 回复具体回复 | 同上并验证主评论与目标回复 | 展示“回复 被回复昵称：内容”，仍是两层 | 保留文本和原回复上下文 |
| 取消回复 | 无写操作 | 清除回复目标，文本保留，恢复主评论输入状态 | 无请求 |
| 展开/加载回复 | 有更多数据 | 原型默认先显示 1 条，展开后显示首批，之后每批 20 条 | 正式追加失败在当前区域重试，不丢已显示回复 |
| 删除主评论 | 仅该评论作者，确认影响 | 移除主评论和所有回复，即使回复属他人，准确扣总数 | 取消无变化；失败保留内容 |
| 删除回复 | 仅该回复作者，确认 | 只删该回复；其他回复保留被回复昵称 | 后续不再跳转已删除回复，不能级联删除其他回复 |

发送中应禁重复点击。结果未知时先确认服务端状态，不自动重发；目标在提交前被删时，不能把回复悄悄改成主评论。原型发送是同步本地写入，分页对本地数组切片，没有真实异步评论请求；详见 G06。关联 COMMENT-01～04、UX-05/07。

<a id="interaction-i08"></a>
### I08 列表排序、滚动加载与搜索

首页、搜索按发布时间倒序、笔记 ID 倒序稳定排序，每批 20 条并按 ID 去重；刷新后才纳入滚动期间的新发布笔记。切换关键词清空旧结果、重置批次，只使用当前关键词结果。正式请求需要处理旧请求取消/过期结果丢弃，避免旧词覆盖新词。

初始加载、追加加载、首次失败、追加失败、空列表、空结果和全部结束分开处理；追加失败保留已有卡片并在列表底部提供重试。原型用 `limit += 20` 重绘本地数组，未真实实现游标/快照、网络分页与追加失败 UI，这些属于迁移待补项。个人主页、后台用户管理是常规每页 20 条，翻页回页面顶部。关联 HOME-01～03、USER-06、ADMIN-02、UX-06。

<a id="interaction-i09"></a>
### I09 删除笔记与数据失效

仅笔记作者可删除。确认文案必须说明笔记及相关点赞、评论、回复将一并移除；取消不产生副作用。成功后首页、搜索、本人主页不再展示，原详情显示“笔记不存在或已删除”，原型跳到本人主页。正式以服务端成功为准再移除，并正确处理同时发生的点赞/回复。图片按 I04 解除引用，不直接无条件删除文件。关联 NOTE-04、UX-03/07、NFR-02。

<a id="interaction-i10"></a>
### I10 请求失败、未知结果与不可用目标

| 状态 | 必须呈现/保留 | 后续动作 |
| --- | --- | --- |
| 字段非法 | 对应字段原因和原输入 | 用户修正后手动提交 |
| 明确未成功 | 失败提示、文本、成功上传预览；点赞回到确认值 | 可手动重试 |
| 创建操作结果未知 | 不提示成功，不自动重发，保留表单 | 先刷新/查询确认是否已成功，再决定是否提交 |
| 登录过期 | 登录引导，不丢当前输入，不补发请求 | 用户重新认证后继续 |
| 无权限 | 无权限提示，管理数据不返回、不泄露 | 返回公开页面或合法入口 |
| 笔记不存在/已删 | 统一“笔记不存在或已删除” | 返回首页 |
| 主评论/回复目标失效 | 保留文本与目标上下文，提示刷新 | 用户主动刷新/选择目标 |
| 页面 HTML 加载失败（仅原型） | 当前 DOM 和输入保留，恢复原地址 | 确认“重试”重新加载 |

原型 `mode` 控制部分场景，不代表所有业务操作都已能模拟每种错误；覆盖矩阵见[差异清单](#prototype-gaps)。关联 UX-01～07。

<a id="interaction-i11"></a>
### I11 后台禁用、启用与统计

账号变更每次确认对象及影响，只能操作普通用户。禁用立即撤销该用户所有会话；启用需重新登录，不能恢复旧会话。状态变更不删除公开内容，不减少其历史公开数据统计。重复同向操作不产生额外副作用。

看板打开和点击刷新获取数据，不要求轮询。统计按北京时间自然日计算；七天含今天和之前六天，无数据补零，今天截至统计时间。统计口径详见 [A01](#page-a01)。不增加账号删除、管理他人笔记或后台内容审核。关联 ADMIN-01～04、PERM-01～03。

<a id="interaction-i12"></a>
### I12 原型导航与生命周期（正式迁移移除）

所有脚本通过经典 `defer` 按依赖顺序加载一次，共享同一运行时，并非 ES module。页面首次访问从当前 HTML 记录 `#app` / `#templates`；切换时加载目标 HTML、DOMParser 解析并挂载这两个区域，不执行载入 HTML 的 script。已加载布局缓存在内存，页面业务模块重新绑定数据。

快速导航用 AbortController 和序号只接纳最新请求；挂载前清理旧页面定时器、重置页面版本。FileReader/Image 异步结果验证页面版本与草稿身份，避免旧任务改写新页面。Hash 切换重置页码、图片序号、回复目标和首页批次，关闭弹窗、滚动到顶部；未保存拦截优先执行。浏览器前进/后退继续走同一流程。

保留内存是为了演示密码、评论暂存、编辑输入在轻量导航后仍可使用；不是要求生产前端保留这套自制路由。真实迁移交给 Controller 和正常页面链接，局部异步操作仍需要相同的过期结果处理。关联 UX-01/05、NFR-02/05。

<a id="pages"></a>
## 5. 全部页面设计

各页均应用第 2～4 节公共规范。下述“迁移验收”是前端验收关注点；完整正式验收仍以 PRD AC 编号为准。页面不单独指定的新规则不得覆盖共享规则。

### U01 首页 / 发现

| 点击作者 | 用户可公开展示 | 进入 U08 | 用户不存在显示不可用 |

| 触发操作 | 校验/权限 | 成功结果 | 失败反馈 |
| --- | --- | --- | --- |
| 编辑资料 | 当前主页属本人 | U09 | 非本人不显示，直达设置仍按本人身份 |

**条件状态**：本人/他人、无简介占位“还没有填写简介，生活的故事正在发生。”；无笔记“还没有发布笔记”，本人“去发布”，他人“返回首页”；用户不存在状态有返回首页入口；加载和失败不能替代公开资料权限。

**Thymeleaf 与验收**：服务端返回公开资料投影，管理字段不能仅依靠 CSS 隐藏；作者资料更新后卡片、正文和评论显示最新头像昵称。本人内容操作通过详情入口即可，不另造卡片菜单。验收 AC-03、AC-06/07、AC-08、AC-20。

**字段与数据**：

| 子视图 | DOM 字段 / 控件 | 规则 |

| 触发操作 | 校验/权限 | 成功结果 | 失败反馈 |
| --- | --- | --- | --- |
| 更换头像 | I04 | 仅预览新头像 | 类型/大小/解码错误提示，原头像保持 |

**Thymeleaf 与验收**：资料与改密应使用明确的提交动作和表单对象，禁把只读用户名作为可任意更新字段。密码不回显，验证后安全摘要存储和会话撤销归服务端。成功更新资料再切换头像引用。验收 AC-03/04、AC-14/15、AC-20，覆盖他人不可改、保存失败和退出后后退。

<a id="thymeleaf-migration"></a>
## 6. Thymeleaf 迁移指南

<a id="migration-m01"></a>
### M01 迁移边界与推荐顺序

迁移保留第 2～5 节的布局和交互，将模拟读写替换成服务端确认的真实行为。这里不规定真实 URL、Java 类名、数据库结构或文件存储供应商。推荐按：首页/搜索 → 详情互动 → 发布编辑 → 登录与设置 → 后台逐页联调；身份框架先提供必要基础，页面次序不是服务端依赖实现顺序。

建议把视图移到 Spring 工程的 `src/main/resources/templates/`，CSS/JS/预置展示素材移到 `src/main/resources/static/`。这两个路径是迁移目标，不表示当前原型已在其中运行。用户上传文件不作为构建时静态素材打包，应由文件服务返回可用地址。保留 `docs/prototype/` 作为设计与回归参照。

<a id="migration-m02"></a>
### M02 公共布局、片段与首屏

| 原型区域 | 迁移方式 | 保留事项 |
| --- | --- | --- |
| 用户端 sidebar/topbar/mobile-nav | 提取 `th:fragment`，页面引用 | 登录/游客/管理员入口、断点和层级 |
| 后台 sidebar/topbar/menu | 独立后台片段 | 不混入用户端底部导航或后台内容管理 |
| 卡片、评论、回复、分页、状态反馈 | 可复用片段 | 结构、计数、本人按钮及可访问名称 |
| 表单和设置两种子视图 | 独立表单片段或页面区块 | 原字段语义、校验错误、回填和密码不回显 |
| 弹窗、抽屉、Toast | 公共容器及所需片段 | 焦点循环、Escape、取消无副作用 |

原型 `<template>` 不会直接显示内容。首屏列表必须把模板内部结构放到可见 DOM，再用 `th:each` 渲染，不能只给隐藏的 `<template>` 加 `th:each` 就认为列表已完成。后续上传缩略图或客户端新增项仍可保留必要 `<template>`；避免同时生成两个首屏或重复绑定事件。

<a id="migration-m03"></a>
### M03 数据绑定与表单回显对照

| 原型机制 / 标记 | Thymeleaf 对应 | 注意事项 |
| --- | --- | --- |
| `bind()` / `[data-bind]` / `textContent` | `th:text` | 正文换行用现有 CSS，用户文本不转成未转义 HTML |
| 动态图片 / 链接 | `th:src` / `th:href` | 正常站内地址和上下文路径；不沿用 Hash 作为服务端地址 |
| `data-like`、内容 ID、回复目标 | `th:attr` 等属性绑定 | ID 来自可信视图数据；服务端再验证归属 |
| 模板克隆列表 | 可见 DOM + `th:each` | 结果顺序、稳定 ID、空态与分页均保留 |
| `show()`、`hidden`、本人判断 | `th:if` / `th:unless` 等条件 | 可见性不替代安全权限；公开资料数据投影必须正确 |
| 字段 `.value`、`data-error` | 表单对象绑定、`th:field`、`th:errors` 或等效错误呈现 | 当前 `name` 与未来字段绑定显式映射，不虚构现有 DTO |
| 原型客户端 submit | 明确 form action/method + 服务端处理或局部请求 | 成功跳转防止刷新重复提交；失败回显本次有效输入 |
| 密码 / 确认密码 | 空密码输入 + 错误状态 | 不在响应 HTML、URL、浏览器存储或日志回显敏感值 |
| `#images` / `#avatar-file` | 明确实际文件上传与关联方式 | 当前只有 id；需补实际 name 或异步上传协议，不把 data URL 当生产存储 |

账号状态、角色、服务端敏感信息不进入公开视图；“本人”与“管理员”来自服务端认证上下文，而非用户提交字段。真实写请求落实 CSRF 保护、服务端长度校验和资源权限校验。文件安全、摘要算法和会话撤销由相应服务实现，本 Spec 不设定其具体接口。

<a id="migration-m04"></a>
### M04 页面数据责任与局部更新

| 页面组 | 服务端首屏/处理责任 | 浏览器保留责任 |
| --- | --- | --- |
| U01/U02/U08 | 当前用户上下文、公开资料、结果列表、排序、总数/下一批信息 | 瀑布流样式、滚动触发、后续批次、点赞反馈 |
| U03 | 有效笔记、作者、本人权限、图片顺序、总数、首批主评论/回复 | 图片轮播、回复目标、展开、局部提交/删除、数值同步 |
| U04/U05 | 认证/归属、原笔记回填、字段错误、原图标识、整体保存 | 预览、计数、上传状态、排序移除、未保存确认 |
| U06/U07/U09 | 认证、注册唯一性、资料/密码校验、会话、错误回显 | 轻量提示、选项卡、头像预览、退出确认 |
| A01/A02 | 管理权限、筛选分页、统计、资料数据与账号状态变更 | 图表、筛选控件、抽屉、确认、刷新反馈 |

服务端需要返回哪些数据见各页“数据与字段”，其载体可为 Model 属性、HTML 片段或正式约定的响应；不能从本文推断某种 JSON wire shape 已被确定。无论使用表单还是异步请求，都遵守 I02、I05、I07、I10 的成功/失败语义。异步批次和搜索带当前查询上下文，过期响应不覆盖新页面。

<a id="migration-m05"></a>
### M05 替换模拟层并移除原型机制

| 当前代码/状态 | 正式迁移处理 |
| --- | --- |
| `RednoteSeed`、本地 `db`、`user()` / `note()` / `listNotes()` / `listUsers()` | 替换为服务端可信查询；页面不直接操作内存集合作为成功凭据 |
| 页面中的 `push/splice/filter`、直接改 likes/status | 接入真实创建/删除/状态操作，确认后更新展示，处理失败和未知结果 |
| `rednote-prototype-v1`、`rn-likes` localStorage | 不再作为正式业务数据或权限来源；如需清除只清原型键，不清站点全部存储 |
| `rn-user` sessionStorage | 不再作为认证凭据，使用真实会话/认证上下文 |
| 内存 `passwords` Map | 完全移除；不能在前端验证真实密码或提供演示密码兜底 |
| `draft` / `commentDrafts` | 保留必要临时输入保护，不能自动升级为公开“草稿”功能；刷新后的恢复另需产品决策 |
| `mode`、演示面板、演示凭据、模拟 400ms | 正式产品移除；使用实际请求状态和服务错误 |
| Hash/HTML fetch、DOMParser、`pageDocuments` 缓存 | 移除原型导航，由 Controller 和正常链接处理完整页面；保留必要局部异步任务取消 |
| 固定发布时间、固定 7 天趋势和示例头像颜色 | 接入真实时间和统计，默认头像仍可按设计生成 |

各页面当前按经典 `defer` 共享变量加载；不要在迁移时只把某页脚本改成 `type="module"` 而不改依赖。保留 JS 的部分应明确依赖、初始化与销毁，不重复注册事件；对话框和局部渲染同样需要避免重复 DOM ID。

### M06 迁移完成检查

每页迁移后，用相同内容、身份和视口与原型对比；核验布局、首屏、按钮条件、字段错误、失败输入保留及成功后的列表同步。然后补足 G 系列差异和对应 PRD AC 场景，再进入下一页。不能因“原型能点通”跳过后台权限、文件引用、并发或会话验证；也不能以接入真实数据为由重新设计页面。
