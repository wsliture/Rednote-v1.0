# Thymeleaf 迁移指南

这版原型保留旧版界面、Hash 链接、交互和浏览器数据，重构的是代码组织。服务端尚未实现，本文的数据名称是页面视图契约，不是已经存在的 Java 类型或接口定义。

## 从哪里阅读

1. 先读对应 HTML 的 `.content`：页面布局、表单、字段名和操作入口都在这里。
2. 再读文件底部 `#templates`：重复项及弹窗。每页只包含自己会使用的模板。
3. 查对应 `js/pages/` 脚本：数据填充、校验、成功跳转、失败反馈和业务按钮处理。
4. 公共 DOM 操作在 `js/ui.js`，模拟数据与运行状态在 `js/store.js`，原型导航在 `js/navigation.js`。`js/events.js` 仅绑定一次公共委托，再调用各业务处理函数。

脚本使用经典 `defer`，按 HTML 中的顺序加载一次，共享同一个运行时；不需要打包。它们按职责拆分，不是 ES module。`app.js` 只启动导航。

## 绑定方式如何替换

| 当前原型 | Thymeleaf 迁移方向 |
| --- | --- |
| `data-bind`、`data-name` 等语义标记，脚本 `textContent` / `value` 赋值 | 普通文本用 `th:text`，表单结合表单对象绑定；保留原有 class 和 DOM 层级 |
| 图片 `src`、链接 `href`、数据属性 | 使用 `th:src`、`th:href`、`th:attr` 绑定真实数据；静态素材迁移到 Spring 静态资源目录 |
| 克隆卡片、评论、回复、图片项、表格行 `<template>` | 将模板内容放入实际可见列表，使用 `th:each` 服务端渲染；不要把首屏内容留在浏览器不展示的 `<template>` 中 |
| `show()` 控制本人入口、管理员入口、空态 | 服务端用 `th:if` / `th:unless`；仍须在服务端验证权限和资源归属 |
| 每页重复的侧栏、页头、手机导航、公共弹窗 | 按 HTML 中注释提取 `th:fragment`，各页面引用；保留用户端与后台两套外壳 |
| 字段旁 `.error` | 接收服务端校验结果，保留当前值与图片预览，不用通用提示替代字段原因 |

当前 HTML 保留了可阅读的示例内容；运行时以模拟数据覆盖。`data-bind` 是原型标记，不是新的模板语言，无需为它实现解释器。

## 服务端与浏览器分工

- **未来 Controller / 服务端**：完整页面首屏、登录身份、权限检查、搜索和分页结果、字段校验与错误回显、业务保存和统计。真实表单需补充提交方式、动作地址与 CSRF；不要把原型按钮的客户端权限判断当作后端防护。
- **继续使用 JavaScript**：图片选择和预览、排序、计数、弹窗焦点、未保存离开确认、图片切换，以及需要局部更新的点赞和评论操作。滚动加载依旧分批获取真实数据。
- **替换模拟数据层**：移除 `RednoteSeed`、localStorage 模拟业务数据和内存密码，替换 `user`、`note`、`listNotes`、`listUsers`、`save` 及页面中的模拟增删改为实际服务结果。最终计数与状态以服务端确认为准。
- **移除原型专用部分**：演示面板、Hash 导航、独立 HTML 的 fetch/DOMParser 加载、运行时模板缓存。迁移后使用正常服务端链接，路由名称由正式开发统一确定；本文不预先规定接口路径。

## 状态与失败反馈

- 注册成功去登录；登录返回原受限页，用户自行继续提交。原型评论暂存和演示密码保存在内存中，轻量导航不会刷新整个文档；完整刷新仍遵循旧版演示密码重置行为。
- 发布/编辑保留草稿直到保存成功或确认放弃；取消编辑、离开页面和浏览器刷新均保留原来的确认行为。上传失败可单张重试，失败未处理时不允许发布。
- 评论成功才清空，失败保留内容；回复目标失效不自动切换回复对象。删除主评论明确说明回复会一并删除。
- 删除笔记、禁用/启用账号均先确认；管理员身份不授予删除他人内容的权限。头像仅在保存成功后生效。
- HTML 加载失败不替换当前 DOM，恢复原链接并提供重试。快速导航以最后一次请求为准；挂载新页面时清理旧页面定时器，图片异步读取以页面版本校验，避免旧任务污染新页面。
- 原型异常模式、客户端图片验证和会话撤销提示都只是演示，真实服务端、安全、文件引用清理与并发行为仍按 PRD 实现。

## 公共片段维护约定

目前各 HTML 都带完整外壳与必要模板，便于单页阅读和后续迁移，不在运行时拼接外壳。调整公共导航或公共模板时，应同步所有使用它的页面；调整业务布局只改对应页面。迁移 Thymeleaf 后通过真正的公共片段消除这些重复。

建议逐页迁移：首页与搜索 → 详情互动 → 发布编辑 → 登录设置 → 后台。每步对照原型外观及回归用例，避免一次性重写布局和业务规则。
